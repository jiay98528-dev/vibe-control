# vibe-control 0.3.6 自动推进与人工复核仪表盘需求

## 目标

- 新项目在 bootstrap 前显式选择手动推进、自动本地推进或自动推送推进；未选择不得写入控制面。
- 自动模式在普通阶段不等待人工确认，依据已锁定目标、任务、检查点和权限持续规划、委派、实现、验证与里程碑提交。
- 自动推送只允许已明确绑定的现有 upstream 分支，且不得 force-push、merge、rebase、创建远端、PR、tag、release 或执行自动接受。
- 到达固定人工复核点、边界变化、R3/不可逆操作、硬失败、推送冲突或用户中断时立即停止。
- 停止时生成离线、自包含、只读派生的本地状态仪表盘与文字摘要，且不得用其授予 evidence、PASS 或 claim。

## 固定边界

- 版本为 `0.3.6`，核心 Schema 保持 `3.2`，自动化策略使用向后兼容的 Schema `1.0`。
- 包姿态保持 `DEVELOPMENT_DIAGNOSTIC`，`formalClaimsAllowed=false`，最高声明为 `DEVELOPMENT_CHECKED`。
- 现有 Schema 3.2 项目缺少策略时保持手动；选择加入使用内容绑定的 plan/apply，不执行整体迁移。
- 主线程唯一负责控制面、整合、里程碑提交和推送；worker 不得修改目标、合同、case/oracle 或批准人工检查点。
- 不创建 release/audit tag 或 GitHub Release，不修改 Pulse、VibeCodingGovernance 或其他项目。

## 验收检查点

1. 新 bootstrap 缺少明确自动化选择时在写文件前稳定阻断；旧项目缺少策略时继续按手动模式解析。
2. 获授权的自动流程跨普通阶段持续推进，并在固定人工复核点停止，不把进度更新变成阶段性批准请求。
3. commit/push 权限绑定精确任务与 Git 目标；越界、漂移、远端冲突或禁止操作稳定 fail-closed。
4. 人工复核点生成同源 `index.html`、`status.json` 与 `summary.md`，离线可读、响应式、可访问且不改变控制状态或声明资格。

本文件与用户批准的《vibe-control 0.3.6 自动推进与人工复核仪表盘》计划共同构成本任务需求事实源。
