## FT-033-01：预设检查点闭合后停止

首次测试发现一个真实的 `CURRENT_GOAL_DEFECT`：单次 review 的第四项普通探索发现会命中 `HC-AUDIT-EXPLORATION-BUDGET`，但失败 review 不留持久记录；同一候选可以换一组 finding ID 再提交三项探索发现并获得审核通过。这违反“每个候选最多三项”和“闭合后停止”的锁定目标。

最小修复是候选级 `audit-closure`：首次超出预算时写入候选、task、commit、checkpoint hash、失败 review、finding IDs 和关闭原因。后续同一候选的开放式审核稳定命中 `HC-AUDIT-STOP-CLOSURE`；继续调查只能建立新任务或新候选边界，不能删除关闭记录重置预算。

修复后复测同一候选 `candidate-TASK-001-0abb675cb2dd`：

- 第一次四项探索发现：exit 3，`HC-AUDIT-EXPLORATION-BUDGET / FAIL`，生成 closure；
- 第二次更换四项 finding：exit 2，`HC-AUDIT-STOP-CLOSURE / BLOCKED`；
- 第三次更换为三项 finding：exit 2，同一 stop-closure blocker；
- phase 始终保持 `VERIFIED`，closure 内容未被后续尝试改写。

## FT-033-02：检查点外的最低核心违规

测试使用同一个未预设在 checkpoint 中的 `MINIMUM_CORE_VIOLATION`：

- 有效 core control 引用与非空 evidence 能被接纳，并阻断 `VERIFIED`；
- 缺少 `coreControlRefs` 和 `evidenceRefs` 时，Schema、task scope 与 core-ref 检查 fail-closed，该 finding 不会进入 claim admission。

这证明检查点停止边界没有压制最低安全与证据核心，但也没有让无引用的严重度标签自行扩张为 blocker。
