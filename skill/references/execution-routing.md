# 自动协作、执行瘦身与审核分离

在规划实现、派发工作、冻结候选或组织验证时读取本文件。目标是让模型在合同内充分发挥能力，同时把完整验收和审核留给不同上下文。

## 固定角色

| 角色 | 负责 | 禁止 |
| --- | --- | --- |
| Coordinator | 目标与合同、控制面单写、路由、整合、候选、里程碑提交、仪表台和用户沟通 | 不把 worker 回报直接当 PASS；不代替 Owner 批准 |
| Implementer | 按轻量 run-card 修改授权文件并运行最小开发检查 | 不改目标、case/oracle、checkpoint、状态或最终结论；不运行无关全量门禁 |
| Executor | 候选冻结后运行锁定 case、保存原始执行结果 | 不修产品代码、不改验收标准、不批准人工门 |
| Auditor | 在新鲜只读上下文核对候选、预期、原始证据和声明边界 | 不接收实现答案或预期总裁决；不顺手修代码 |
| Owner | 产品方向、主观质量、权限、不可逆操作和最终复核 | 不承担逐文件、逐哈希和计数核对 |

同一上下文可以在宿主能力不足时串行承担多个角色，但必须降低独立性声明；它不能通过改名伪装角色分离。

## Implementer 的轻量 run-card

只提供：当前目标和非目标、允许/禁止路径、相关事实源、里程碑节点、外部可观察检查点、最小开发检查、停止条件和回报格式。不要提供完整保证矩阵、历史审计答案、发行封印流程或“应当发现的缺陷”。

Implementer 只运行能快速发现本次改动明显错误的格式、类型、窄单测或目标 smoke。不得为了制造更多 PASS 盲跑全量测试、深度对抗套件、正式 package validator 或与改动无关的门禁。失败若能在原合同内修复则继续；需要改变目标、范围、case/oracle、权限或风险时回报 Coordinator。

## 项目派生验证策略

Coordinator 在候选执行前从关键目标、里程碑、检查点、Profile、适配器证明边界和最低证据核心生成 `verificationStrategy`。它至少列出：

- 每个检查点由哪个 case、Executor 或人工门证明；
- 哪些开发检查只供 Implementer 快速反馈；
- 哪些完整执行只能在冻结候选后进行；
- Auditor 获得的输入、探索预算和停止条件；
- 尚未证明与明确排除的范围。

策略在 task lock 中绑定。实现或审计期间不得为了“再找一些问题”临时扩大 case、威胁模型或门禁。新增建议进入后续候选；只有当前目标缺陷、最低核心违规、锁定安全边界或明确权限冲突可进入当前阻断。

## Guard 语义

- `ACTION_GUARD`：路径/权限越界、R3、不可逆动作、远端冲突或未授权副作用；立即停止动作。
- `CLAIM_GUARD`：测试失败、缺证据、skip、零计数、绑定或漂移问题；不得提高声明，但允许在原合同内继续诊断和修复。
- `HUMAN_DECISION`：产品方向、主观质量、范围或授权；停到 Owner。
- `ENVIRONMENT_BLOCKED`：缺工具、环境或外部状态；停止并说明恢复条件，不能写成产品失败。
- `ADVISORY`：风格、普通流程改进、未来加固或当前目标外探索；记录建议，不阻断执行或声明。

`ADVISORY` 不得因严重度标签变成 blocker。固定阶段顺序、固定风险到审核形式、固定审核次数和一般质量卡点是启发式建议，不是跨项目硬门禁。确定性最低核心仍按 [evidence-policy.md](evidence-policy.md) fail-closed。

## 候选后的执行与审核

Coordinator 复核 diff 和文件所有权后冻结唯一候选。Executor 使用锁定 case 在候选环境执行；Auditor 再在未泄漏实现答案的新鲜只读上下文检查逐项结果。Auditor 完成 required checkpoint 后停止；普通探索遵守候选级预算，不通过更换会话重复开放审核。

完整执行或审计失败后：

1. 若是原合同内可复现缺陷，Coordinator 建立修复节点并重新派给 Implementer；
2. 若两次失败具有相同根因且没有产品或控制输入变化，停止为 `PAUSED_NO_PROGRESS`，避免无变化重跑；
3. 若需要改变边界，停止并交给 Owner；
4. 若只是 advisory，加入后续建议并继续当前闭包。

自动路径到候选闭合也必须停到一次 Owner review。Executor、Auditor、Team 或 SubAgent 都不能调用 `accept`、批准 `HUMAN` checkpoint、push、tag 或 release。
