# 模型路由

在需要分派执行上下文、创建工作树或执行审核前读取本文件。模型选择是可解释的能力匹配，不是质量、可靠性或成功概率的承诺。

## 先解析协调后端

模型选择与协调载体是两个独立问题。先按 [multi-session-routing.md](multi-session-routing.md) 枚举当前宿主真实工具并解析 `CODEX_THREADS | SUBAGENTS | SERIAL`，再为其中的 responsible、worker、auditor 角色选择模型。非 Codex 宿主没有 thread/cursor 能力时，只要具备子智能体工具，就显式使用 `SUBAGENTS`；两者都没有时使用 `SERIAL`。

不得因某个模型支持长上下文就假定它支持 Codex 跨会话工具，也不得因 Skill 不设置固定 worker 数量上限就超过宿主容量、文件所有权或隔离条件。

## 固定优先级

按以下顺序解析；前一层的禁止或明确选择覆盖后一层：

1. 平台/系统实际可用模型与安全限制。
2. 项目元指令中的模型禁令、能力上限和角色限制。
3. 用户对本任务的明确模型指定。
4. 已确认的项目 `model-routing.json` 配置。
5. 本文的启发式建议。

不得选择被前述任一层禁止的模型。无可用候选时报告“无法安全路由”，不要用未批准模型兜底。

## 运行时事实与资料来源

每次首次路由先枚举当前会话实际可调用的模型、思考强度、工具和工作树能力；不要把文档、历史会话或模型自述当成运行时能力。

为每个允许模型保存七维 `0..100` 能力画像：

| 维度 | 含义 |
| --- | --- |
| `implementation` | 常规编码与局部实现 |
| `architecture_reasoning` | 跨模块设计与因果推理 |
| `long_context` | 长历史、长文档与多证据整合 |
| `tool_reliability` | 工具调用、命令执行与状态遵守 |
| `verification_audit` | 复现、反证、证据核验与审计 |
| `latency` | 交互响应速度（高分表示更快） |
| `cost_efficiency` | 在项目预算中的性价比（高分表示更省） |

向量必须附带来源、采集时间、置信度和适用范围。来源优先级：

1. 运行时枚举与项目内实际任务记录；
2. 官方模型卡、能力/上下文/定价文档；
3. 基准组织者发布的原始结果与任务定义；
4. 模型自身知识或经验判断，仅可作为待核验假设。

不得把七维压成总分、排行榜或“最强模型”。路由时只说明任务所需维度、排除条件和取舍。

## 缓存与项目快照

全局研究缓存保存于 Skill 管理目录，默认有效期 90 天。缓存至少含来源 URL 或本地出处、抓取日期、摘要、画像、置信度及失效日期。模型名单、平台能力或项目禁令变化时立即失效并重新枚举。

首次为项目确认路由时，在 `.vibe-control/model-routing.json` 保存不可变选择快照：运行时枚举结果、协调后端、观测到的协调能力、`NO_SKILL_FIXED_LIMIT` 数量策略、来源引用、能力向量、选择理由、排除项、用户确认和生成时间。项目快照不会因全局缓存刷新而静默改写；只能由显式 `configure-models` 更新。

## 低置信降级

官方资料缺失、联网不可用、运行时无法枚举或画像过期时：

- 标记 `confidence: low` 与具体缺口；
- 仅路由到项目明确允许且角色风险较低的任务；
- 对高风险、发布、安全、数据破坏或最终裁决任务，要求用户选择或保持 `BLOCKED`；
- 不得因“模型看起来够强”越过角色分离、候选冻结或证据要求。

## 角色匹配

- 调查、盘点、固定检查：优先工具可靠、延迟合适且被项目允许的轻量模型。
- 局部实现：优先实现能力与工具可靠性满足任务合同的模型。
- 跨模块设计、复杂归因：优先架构推理和长上下文，但仍受项目上限约束。
- 独立审核：优先验证审计能力；审核者不得是同一交付循环的实现者，也不得接收预期结论。

模型选择不改变任务合同、文件所有权、风险等级或验收标准。无法满足任务所需能力时，缩小任务、升级人工决策或暂停，而非伪造充分性。
