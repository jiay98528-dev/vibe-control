# vibe-control 0.3.3 已确认需求

状态：`CONFIRMED`  
来源：用户批准的“vibe-control 0.3.3 检查点契约补强计划”  
包姿态：`DEVELOPMENT_DIAGNOSTIC`，最高 `DEVELOPMENT_CHECKED`

本版本解决一个具体失控点：任务开始前没有锁定“每个里程碑检查点预期看到什么结果、哪些结果不构成证明、何时审计必须停止”，导致审核者为了产出发现而扩大审计面，并把真假问题的裁决压力转回给产品负责人。

实现范围：

- 将定位阶段的 success signal 与 human quality gate 改为内容派生 ID 的稳定对象。
- 在任务合同中锁定 acceptance checkpoint、逐项 assertion、类型化预期、声明上限、未证明范围和一次性确认记录。
- 将检查点集合哈希传播到 task lock、candidate、evidence、review、owner decision 与 handoff。
- 由控制器从原始 evidence 重算自动检查点结果；人工检查点只能由 owner 逐项决定。
- 固定审计为合规检查加最多三项普通探索发现，检查点报告闭合后停止。
- finding 只有在当前任务、明确声明、最低核心或 KF 安全范围内才可阻断。
- 提供 3.1 到 3.2 的两阶段、内容绑定、可恢复迁移；旧下游证据不得继承。

非目标：

- 不让控制器解释自由文本是否“合理”或替代产品判断。
- 不创建正式 release tag、audit tag 或 `FORMAL_GATE_READY` 声明。
- 不修改 Pulse、Governance 或其他项目。
- 不扩大到恶意维护者与 verifier 串通的威胁模型。

验收边界：Schema、引用闭包、哈希、候选传播、oracle 观察、逐检查点 review、逐人工门 decision、finding 范围、探索预算和迁移原子性由确定性回归验证；主观质量仍由一次 owner 决定。
