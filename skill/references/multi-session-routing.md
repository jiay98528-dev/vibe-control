# 多执行上下文兼容路由

在需要并行开发、独立审计或跨上下文恢复时读取本文件。目标是控制面单写、工作可并行、结论可回溯；不是依赖某个产品独有的会话 API，也不是追求最大并发。

## 能力探测与兼容后端

先枚举当前宿主实际可调用的协调工具，再且只解析一个后端。不得根据“Codex”“Claude”“Agent”名称、模型自述、静态文档或历史运行推断能力。

| 后端 | 选择条件 | 映射 |
| --- | --- | --- |
| `CODEX_THREADS` | Codex 的用户可见任务/线程创建、消息、检查和 cursor wait 工具实际可用且获授权 | 负责上下文、worker 与 auditor 映射为独立 Codex 任务；仅此模式使用 cursor 语义。 |
| `SUBAGENTS` | `CODEX_THREADS` 不可用，但子智能体 spawn/message/wait 工具实际可用 | 所有“跨会话”worker/auditor 角色显式降级为子智能体；父智能体仍是负责上下文和控制面唯一写入者。 |
| `SERIAL` | 上述两类协调工具均不可用 | 由负责上下文串行执行；审核只能标记为非独立，不能伪造并行或隔离。 |

非 Codex 宿主只要具备子智能体工具，就必须选择 `SUBAGENTS`，不能调用不存在的 Codex task/thread/cursor 接口。若宿主同时暴露多种能力，以真实授权和隔离能力选择；不要为了形式上的“跨会话”放弃更可靠的可用后端。

数量策略固定记录为 `NO_SKILL_FIXED_LIMIT`：Skill 不设置 worker 或子智能体的固定数量上限。实际派发数量只由宿主容量、有用的独立任务数、文件所有权和隔离条件约束。不得把旧的默认数字继续写入项目配置，也不得把“无 Skill 上限”解释为无边界批量派发。

## 角色与写入边界

负责上下文是控制面的唯一写入者，负责任务合同、文件所有权、执行上下文派发、候选冻结、证据收口、状态声明和用户沟通。它必须复核 worker 的结果；Codex 任务或子智能体回报都不构成正式通过。

Worker 只能在任务包授权的范围内读写。它们不得修改：

- 治理锁、固定 case、oracle、阶段状态或最终声明；
- acceptance checkpoint、assertion、确认记录或审计预算；
- 其他任务的文件所有权；
- 用户未授权的产品范围、依赖、权限或发布状态。

Auditor 必须在候选冻结后使用新鲜、只读、与实现者身份分离的上下文。`CODEX_THREADS` 使用新任务；`SUBAGENTS` 使用新建且未接收实现答案的审计子智能体。只提供合同、唯一候选、固定 case 和原始证据；不提供预期结论、实现者摘要或先前审计答案。宿主无法提供新鲜隔离上下文时，结果必须标记为非独立诊断。

## 任务包

负责上下文向每个 worker 提供一个受版本管理或可记录的任务包，至少包含：

- 任务 ID、目标、风险等级与停止条件；
- 允许/禁止修改的文件或目录，及唯一所有者；
- 事实源、固定 case、验收命令与候选基线；
- 允许的工具、模型约束、是否可写、是否需要工作树；
- 回报格式：改动、命令/退出码、case counters、产物、失败/skip、未决问题。

任务包不含“应如何实现”的非必要策略。边界内由模型自主选择实现方案；边界外先回报，不得自行扩权。

## 授权与并行

手动模式在创建用户可见的 Codex 任务前，每个开发任务只确认一次授权；自动模式的已确认策略就是该任务内有界 worker 派发的一次性授权，普通阶段不得再次停下来确认。`SUBAGENTS` 仍按当前宿主和会话的实际委派权限执行；不得假造“跨会话”能力，也不得要求用户反复确认一个任意数量配额。任务仍需固定角色、所有权和风险范围，但不固定 Skill 级数量上限。

并行写入必须使用隔离 worktree，且任务文件所有权互不重叠。只读调查可共享目录，但不得写入状态或证据。无法建立 worktree、不能可靠区分所有权或发现脏工作区时，降级为串行执行或只读诊断。

Worker 不得自行 merge、rebase、发布、修改任务合同或接管其他执行上下文。负责上下文负责 diff 复核、冲突处理和唯一候选的建立。

## `advance` 自动推进路由

`advance` 是 Skill 工作流，不是独立 CLI。只有治理锁与 task lock 引用同一个有效 automation policy 时才可按自动模式运行；旧 Schema 3.2 项目缺少策略时保持 `MANUAL_STAGE_CONFIRMATION`，不能从宿主具备子智能体或线程能力推断自动授权。

负责上下文按实际能力解析一次 `CODEX_THREADS → SUBAGENTS → SERIAL`，然后执行“计划 → 委派/实现 → 验证 → 整合 → 里程碑提交 → 可选推送”。普通阶段只发送非阻塞进度更新，不因 worker 完成、局部测试通过或准备进入下一实现步骤而暂停等待批准。后端降级不改变自动化权限，也不能提高角色独立性声明。

只有负责上下文可以调用 `automation --action commit|push`。检查通过、文件归属清楚且改动仍在合同范围内时，`AUTO_LOCAL_TO_REVIEW` 和 `AUTO_PUSH_TO_REVIEW` 都允许里程碑提交；后者还允许向策略绑定的既有 remote/upstream 非强制推送。Worker、auditor 和其他任务不得提交控制面、推送、批准 checkpoint 或调用 `accept`。自动路径永远不允许 merge、rebase、创建 remote/PR/tag/release、force-push 或擅自扩大权限。

出现候选闭合、`HUMAN` checkpoint/owner decision、目标或其他锁定边界变化、R3/不可逆操作、硬失败、推送冲突或用户中断时，所有后端都必须停止。负责上下文随后生成外部缓存 Dashboard 的同源 `index.html`、`status.json` 和 `summary.md`，呈现唯一待人工决定事项。该投影不构成 evidence、审核或批准。

## 候选与审核

所有执行结果先回到负责上下文；负责上下文将可验收改动冻结为唯一候选，再执行确定性检查。候选冻结后若源码、合同、checkpoint/assertion、case、oracle、校验器或受管输入变化，旧证据按失效规则处理，不得继承。

Auditor 只获得锁定 checkpoint、case/oracle、候选和原始证据接口，不获得候选实际结果、实现者摘要、已知缺陷清单或预期总裁决。全部 required checkpoint 已报告且最多三项普通探索发现预算用尽后必须停止；没有新候选、合同变化或用户授权，不得更换任务、子智能体或 finding ID 重复启动开放式审核。

审核预算属于候选而不是执行后端。某个 auditor 提交第四项普通探索发现后形成的 `audit-closure` 对所有后续 Codex 任务、子智能体或串行复核生效；更换 session、review ID 或 finding ID 不会重置预算。

独立审计只检验冻结候选及其绑定证据。发现哈希不一致、缺引用、skip、零执行计数、开放高优先级问题或无法复现时，只能失败闭合或缩小声明，不得代替实现者修补后给出通过。

## 等待与降级

- `CODEX_THREADS`：使用 cursor 增量等待，单次最长 60 秒；每 300 秒最多生成一次未变化状态的聚合摘要。
- `SUBAGENTS`：使用宿主原生 mailbox/wait/notification 机制；不要轮询或调用不存在的 Codex cursor。等待结果不是执行证据。
- `SERIAL`：直接执行，不建立虚构的等待循环。

缺少 worktree 时禁止并行写入；缺少只读或新鲜上下文隔离时禁止宣称独立审核；缺少任何协调后端时使用 `SERIAL`。收到完成、失败、阻断或用户消息时立即处理，不要反复读取未变化的全量上下文。

任何降级都不得被写成等价的独立审核、并行隔离或正式放行。兼容层只替换协调载体，不降低候选绑定、证据、检查点、审计停止条件或角色分离标准。
